## 1. Сквозная ссылка «Контакты» ведёт на 404 — КРИТИЧНЫЙ

- **Где:** ссылка с анкором «Контакты» на `https://t-ind.ru/contact` → HTTP 404. В выгрузке 4xx-ссылок 2 204 ссылки, из них **2 198 — на `/contact`**, со всех страниц (главная, категории, карточки товаров). Позиция ссылки — основной блок меню/футера (`//body/div[4]/ul[3]/li[3]/a`).
- **Почему важно:** пользователь не может найти контакты (коммерческий фактор, потеря заявок); поисковик тратит краулинговый бюджет на 404 с каждой страницы; ссылочный вес уходит в никуда.
- **Что делать:** исправить ссылку в шаблоне на реальную страницу контактов (проверить, существует ли она; `/kontakty` тоже даёт 404) или создать страницу `/contact` с адресом, телефонами, режимом работы, картой; затем пересканировать.

## 2. Дубли `/page-all` в индексе — ВЫСОКИЙ

- **Пример:** `https://t-ind.ru/catalog/azs` и `https://t-ind.ru/catalog/azs/page-all`; `/catalog/shinomontazhnoe-oborudovanie` и `/catalog/shinomontazhnoe-oborudovanie/page-all`; `/brand/nordberg` и `/brand/nordberg/page-all`. Одинаковые Title и H1 (Screaming Frog: 10 дублей Title, 6 дублей H1 — все пары «страница / page-all»).
- **Факт:** в выгрузке органики 140 разных URL `/page-all` ранжируются по ~2 200 запросам (например, `/catalog/ruchnoj-instrument-dlya-shinomontazha/page-all`, `/catalog/latki-i-plastyri-dlya-remonta-shin-i-kamer/page-all`). Canonical на `page-all` ведёт на основную страницу, но Яндекс канонические адреса как рекомендацию часто игнорирует.
- **Почему важно:** в выдаче может показываться «длинная» версия вместо целевой категории, сигналы делятся между двумя URL, лишняя нагрузка при обходе.
- **Что делать:** выбрать единую каноническую версию. Рекомендую закрыть `page-all` (301 на основную страницу или `noindex` + убрать ссылки на него из HTML) либо добавить `Disallow: /*/page-all` в robots.txt после того, как страницы выпадут из индекса.

## 3. Пагинация: страницы 2+ канонизированы на первую — ВЫСОКИЙ

- **Пример:** `https://t-ind.ru/catalog/balansirovochnye-stanki/page-2` → `canonical = https://t-ind.ru/catalog/balansirovochnye-stanki`. При этом есть `rel="prev/next"`, Title страницы 2 уникален («…, страница 2»), а Description такой же, как на первой странице.
- **Масштаб:** по краулу 305 страниц содержат пагинацию, 102 URL (4,6%) неиндексируемы; пагинируемых страниц 2+ — 94 (в частичном краулe).
- **Почему важно:** canonical на первую страницу сообщает, что страница 2 — дубль первой. Товары с глубоких страниц теряют внутренние сигналы, а Google игнорирует `rel=next/prev`. Частично риск снижает то, что карточки есть в sitemap (25 183 товара).
- **Что делать:** на страницах 2+ ставить self-canonical, уникальный Description, и оставить их индексируемыми; в sitemap включить категории; для крупных категорий (50+ товаров) рассмотреть подкатегории вместо глубокой пагинации.

## 4. Фильтры и сортировки — ВЫСОКИЙ

- **Что хорошо:** комбинации фильтров (`/catalog/balansirovochnye-stanki/brand-sivik/vid-avtomaticheskij`) закрыты `noindex,nofollow`, несуществующие фильтры отдают 404, `?utm=` закрыт в robots.
- **Проблемы:**
  1. Из фильтров генерируются **ссылки на несуществующие страницы (404)** — часть из 6 «нестандартных» 4xx в выгрузке: `/catalog/emkosti/vidtopliva-dizelnoetoplivo`, `/catalog/bloki-porshnevye/proizvoditelnostlmin-420_430_480_490`, `/catalog/porshnevye-kompressory/proizvoditelnostlmin-1210_1260_1300_1325_1350_1390_1400`, `/catalog/katushki-dlya-shlangov/shlangvkomplekte-da`.
  2. Сортировка и параметры не закрыты в robots.txt и отдают 200 `index,follow` с canonical на базовый URL: `?sort=price`, `/sort-price`, `?page=2`.
  3. В индексе (по выгрузке органики) есть «мусорные» URL с лишними символами: `/catalog/nabory-ruchnogo-instrumenta/brand-hans:(`, `…/brand-rockforce:@`, `…/podemniki/brand-astra:C`, `…/brand-atis:m`.
- **Почему важно:** лишние URL расходуют краулинговый бюджет и создают дубли; битые ссылки ухудшают качество сайта.
- **Что делать:** не выводить ссылки на фильтры без результатов; отдавать 301/404 на «мусорные» URL с символами `:`, `@`, `(`; закрыть сортировки (`Disallow: /*?sort`, `/*/sort-`), оставить самоканонические только фильтры с реальным спросом (бренд, тип, 220 В и т.п.).

## 5. Тяжёлые HTML-страницы и медленный ответ — ВЫСОКИЙ

- **Измерения (выборка 240 URL, один регион, gzip включён):** средний размер HTML: товары ≈ 750 КБ, категории ≈ 890 КБ, бренды ≈ 820 КБ, главная ≈ 790 КБ (несжатый вес; для сравнения, нормальная страница — 100–300 КБ). Среднее время ответа 1,5–2,1 с, часть страниц — 3–4 с.
- **Почему важно:** для e-commerce это серьёзный риск по LCP/INP на мобильных и по скорости обхода; страницы такого веса при 25 тыс. URL замедляют индексацию.
- **Что делать:** выяснить, из чего состоит HTML (инлайновые SVG/JSON/скрипты, дублирующиеся блоки меню), вынести в кэшируемые файлы, включить серверный кэш и HTTP-кэширование, ограничить количество товаров/блоков в первом экране; замерить Core Web Vitals в PageSpeed Insights / полевых данных Яндекс.Вебмастера.
- **Картинки:** в скриншоте Screaming Frog (частичный краул, 407 картинок) фильтр «Over 100 KB» показывает 0 — тяжёлые картинки в этой выборке не подтвердились. Но есть: 64 картинки без атрибута `alt` (15,7%) и 384 (94%) без атрибутов размеров — риск для CLS. Тяжёлые изображения стоит проверить после полного краула.

## 6. Title и Description — СРЕДНИЙ

- **Длина:** Over 60 символов у 1 791 страницы (81%), Description длиннее 155 символов у 1 964 (89%). Заголовки карточек: в выборке — в среднем 128 символов, до 155: `«Подъемник четырехстоечный 4,5 тонны Станкоимпорт ПГ4-4.5 (М)…, 220/380В купить в Санкт-Петербурге и Москве с доставкой по России и СНГ!»`.
- **Шаблонность:** Description карточек повторяет название товара и общий хвост «Купить оборудование для автосервиса и АЗС в интернет-магазине…».
- **Нет Description:** 81 страница (3,7%), в т.ч. важные категории: `/catalog/gruziki-balansirovochnye`, `/catalog/kanavnye-podemniki`, `/catalog/gorelki-gazovye`, `/catalog/komplekty-shod-razval`, `/catalog/dlya-shinomontazhnyh-stankov`, `/catalog/pistolety-dlya-nakachki-shin`; в выборке — ещё 14 из 60 категорий и 10 из 30 брендов.
- **Дубли:** 10 дублей Title (пары с `page-all`), 40 дублей Description. Страницы брендов: «Продукция компании Fiac купить…» — шаблон без коммерческого смысла.
- **Что делать:** сократить Title товаров до ~60–70 символов (бренд + модель + ключевая характеристика + «купить»), убрать повтор «Санкт-Петербург и Москва» в каждом заголовке, заполнить Description у всех категорий и брендов, для целевых категорий (балансировка, шиномонтаж) переписать вручную под кластеры из семантики.

## 7. Заголовки H1–H2 — СРЕДНИЙ

- **Главная** `https://t-ind.ru/` — **нет H1** (проверено на живой странице; Screaming Frog показывает H1 missing для 3 URL).
- `https://t-ind.ru/catalog/styazhki-pruzhin` — **7 тегов H1** (в крауле Multiple H1: 4 URL).
- 625 страниц (28%) с H1 длиннее 70 символов (карточки товаров, где H1 — полное название).
- **H2 отсутствует на 92% страниц** (2 028 из 2 202): у категорий нет текстовых блоков и структуры — слабо для коммерческих и информационных запросов.
- Страницы брендов: H1 вида «Nordberg» без описания.
- **Что делать:** добавить H1 на главную, оставить один H1 на странице, добавить на категории SEO-блок с H2 (виды, как выбрать, характеристики, доставка), уточнить H1 брендов («Шиномонтажное оборудование Nordberg»).

## 8. robots.txt и sitemap.xml — СРЕДНИЙ

- **robots.txt:** нет директивы `Sitemap:`; три одинаковых блока для `*`, Yandex и Googlebot (избыточно); `Allow: *.css` / `*.js` без ведущего `/`; `Clean-param` понимает только Яндекс; не закрыты сортировки, `page-all`, `?page=`, `?sort=`; закрыт `/resize/`, но изображения лежат в `/files/resized/` (открыты — это нормально, но проверьте, что нужные ресурсы не блокируются).
- **sitemap.xml:** один файл, 25 775 URL (5,4 МБ) — в пределах лимита (50 000 / 50 МБ). Состав: 25 183 карточки, 340 категорий, 233 бренда. Есть lastmod почти у всех, но `changefreq=daily` и `priority=1.0` у главной и служебных страниц — не несёт смысла. В карте сайта технические и малоценные страницы: `/personal-data`, `/credit`, `/credit_approved`, `/credit_refusal`, `/warranty`, `/warranty-service`, `/discounted`, `/news`, `/all-posts` (контент 2023 года).
- **Что делать:** добавить `Sitemap: https://t-ind.ru/sitemap.xml` в robots.txt; убрать технические страницы из карты; разделить sitemap на индекс (товары / категории / бренды / статьи), чтобы удобнее мониторить индексацию в Вебмастере и GSC; сверить число URL в sitemap с числом проиндексированных.

## 9. Редиректы — НИЗКИЙ

- `https://www.t-ind.ru/catalog/balansirovochnye-stanki` → 301 → `http://t-ind.ru/catalog/balansirovochnye-stanki` → 301 → `https://t-ind.ru/catalog/balansirovochnye-stanki` (**цепочка из двух редиректов**, промежуточный шаг на небезопасный http).
- Корректно работают: `http→https` (одним 301), слэш в конце → 301 на URL без слэша, `/page-1` → 301 на категорию, несуществующие URL → честный 404 с `noindex`.
- **Что делать:** настроить прямой 301 с www и http на `https://t-ind.ru/…` одним шагом.

## 10. Региональность и малоценные страницы — НИЗКИЙ / НАБЛЮДЕНИЕ

- **Региональность:** один домен, на всех страницах в Title «…в Санкт-Петербурге и Москве»; запросы с другими городами (Новосибирск, Иркутск, Воронеж, Владивосток) ведут на общие категории. Страниц под регионы нет — для частотности 15–60 это допустимо, но нужно проверить привязку региона в Яндекс.Вебмастере и наличие страниц «Доставка» / «Контакты» с понятными условиями по РФ.
- **Малоценные страницы:** 233 страницы брендов с шаблонными Title и без текста, их дубли `/brand/*/page-all`; страницы опций `…/optsii` в sitemap (2 URL); 25 тыс. карточек, среди которых запчасти и аксессуары с однотипным описанием. Риск «тонкого» контента на уровне сайта.
- **Что делать:** оставить в индексе бренды с реальным спросом и текстом (Sivik, Nordberg, Hunter, Hofmann, Storm, Sicam), остальные — `noindex` или доработать; для карточек запчастей — уникальные характеристики, применимость; проверить в Вебмастере разделы «Исключённые страницы» и «Малоценные страницы».

## Рекомендуемый порядок работ

1. Починить ссылку «Контакты» (п.1) — быстро, влияет на всё.
2. Определиться с `page-all`, пагинацией и сортировками (п.2–4), доработать robots.txt и sitemap (п.8).
3. Снизить вес HTML и время ответа (п.5), прогнать PageSpeed.
4. Переписать Title/Description/H1 и добавить SEO-блоки на ключевые категории (п.6–7), в первую очередь «шиномонтажное оборудование» и «балансировочные станки».
5. Убрать цепочку редиректов (п.9), навести порядок с брендами (п.10).
6. После правок — полный краул и сверка с Яндекс.Вебмастером и Google Search Console.
